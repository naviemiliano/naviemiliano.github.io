CS180 Project 4: Neural Radiance Field (NeRF)

Overview

In this project, I implemented Neural Radiance Fields (NeRF) to showcase 3D scenes from multi-view images. The project started with camera calibration using ArUco markers, then fitting a neural field to 2D images, and finally training a full 3D NeRF model.

Part 0: Camera Calibration and 3D Scanning

0.1 Camera Calibration

I first calibrated my phone camera using ArUco markers. I took 40 images of the aruco calibration markers from different angles and distances. Using OpenCV's ArUco detector and cv2.calibrateCamera(), I computed the camera intrinsic matrix and distortion coefficients. I also made sure to handle the cases where tags weren't detected. I did this by checking if the detection returned any aruco ids before processing.

0.2 Object Scanning

For the 3D scan, I used a hirono figure and placed it next to a printed ArUco marker. I took 49 photos from various angles while trying to maintain consistent lighting and distance, and avoiding motion blur.

0.3 Camera Pose Estimation

Using cv2.solvePnP(), I estimated the camera pose for each image. The function itself takes in the 3D coordinates of the ArUco tag corners (object coordinates) and their corresponding 2D pixel locations (image coordinates) to compute the rotation and translation vectors. I converted these to camera-to-world transformation matrices for visualization.

0.4 Dataset Creation

After undistorting the images with cv2.undistort(), I packaged everything into an .npz file. I split the data into training (~70%), validation (~15%), and test (~15%) sets. The dataset includes undistorted images, camera-to-world matrices, and the focal length.

Part 1: Fit a Neural Field to a 2D Image

Model Architecture

I implemented an MLP with the following architecture:

  • Input: 2D pixel coordinates (x, y) with sinusoidal positional encoding
  • Hidden Layers: 3 layers with width of 256 neurons each
  • Activation: ReLU between layers
  • Output: 3D RGB values with Sigmoid activation
  • Positional Encoding: L=10 frequency levels (expanding input from 2D to 42D)
  • Optimizer: Adam with learning rate 1e-2
  • Batch Size: 10,000 pixels per iteration
  • Training Steps: 2000 iterations

Positional Encoding: I used the formula from the NeRF paper where PE(p) = [sin(2⁰πp), cos(2⁰πp), sin(2¹πp), cos(2¹πp), ..., sin(2^(L-1)πp), cos(2^(L-1)πp)], concatenated with the original input.

Training Progression

The network learns to represent the image by mapping coordinates to colors. Initially, the output is quite blurry, but as training progresses, fine details emerge. The positional encoding is crucial for capturing high-frequency details.

Part 2: Fit a Neural Radiance Field from Multi-view Images

2.1 Creating Rays from Cameras

I implemented three coordinate transformations:

  1. Camera to World Coordinate Conversion: Implemented x_w = transform(c2w, x_c) which using matrix multiplication to transform a point from camera to the world space.
  2. Pixel to Camera Coordinate Conversion: Inverted the camera to world transformation process implemented above. For a pixel (u,v) at depth s: x_c = s * K^(-1) * [u, v, 1]^T
  3. Pixel to Ray: I combined the two transformations above to compute the origins and directions of the rays. The ray origin is the camera position (c2w[:3, 3]) and the ray direction is computed by transforming a point at depth 1 to world space and normalizing.

2.2 Sampling

Ray Sampling: I implemented a dataloader that randomly samples 10,000 rays from the training images.

Point Sampling: Along each of the rays, I uniformly sampled 64 points between near=2.0 and far=6.0. During training, I add random perturbations to these sample locations to prevent overfitting.

2.4 Neural Radiance Field Architecture

My NeRF network has the following structure:

  • Input: 3D position (x,y,z) with PE (L=10) and view direction with PE (L=4)
  • Architecture: 8 hidden layers with 256 neurons each
  • Skip Connection: Concatenate input features at layer 4
  • Output: Density (σ) with ReLU and RGB with Sigmoid
  • Training: Adam optimizer, learning rate 5e-4, 10K rays per batch
# Simplified network structure Input (3D pos) → PE(L=10) → [63D] ↓ Layer 1-4: Linear(256) + ReLU ↓ Skip: Concat with input PE ↓ Layer 5-8: Linear(256) + ReLU ↓ ┌─────────┴─────────┐ ↓ ↓ Density Branch RGB Branch Linear(1) + ReLU Concat view direction PE(L=4) ↓ Linear(128) + ReLU σ Linear(3) + Sigmoid ↓ RGB

2.5 Volume Rendering

I implemented the discrete volume rendering equation to composite colors and opacities along rays. For each ray with N samples, I compute:

  • Alpha values: α_i = 1 - exp(-σ_i * δ_i) where δ_i is the distance between samples
  • Transmittance: T_i = exp(-Σ(σ_j * δ_j)) for j < i (cumulative product of (1-α_j))
  • Final color: C = Σ(T_i * α_i * c_i) where c_i is the RGB at sample i

Training Progression

The model was trained for about 1000 iterations with a batch size of 10K rays. Training took approximately 10 minutes on a GPU. The PSNR reached over 23 dB on the validation set.

Part 2.6: Training with My Own Data

Implementation Changes

Training on my own captured data required several adjustments:

  • Near/Far Planes: Changed from near=2.0, far=6.0 to near=0.02, far=0.5 based on my scene scale
  • Samples per Ray: Increased from 32 to 64 samples for better quality
  • Training Time: Trained for 6000 iterations (about 45 minutes) for convergence
  • Image Resolution: Resized images to 300×300 to balance quality and training speed

Challenge: Finding the right near/far planes was tricky. Too small a range missed the object, too large wasted samples on empty space. I used Viser to visualize sample points and adjusted iteratively.
